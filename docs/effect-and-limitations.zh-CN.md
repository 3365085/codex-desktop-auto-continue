# 效果与限制

## 同线程继续

Codex 会话日志的元数据包含稳定的线程 ID。某轮以受支持的暂时性错误结束后，
程序调用：

```text
codex queue --thread <原线程ID> --message continue
```

因此下一条消息属于原来的对话。程序不会从旧内容重新拼装原始问题，也不会
新建线程。

## 会保留什么

- 原聊天记录仍属于同一线程；
- 原工作目录与 worktree 关联不变；
- 已经写入磁盘的文件修改保留在工作树中；
- 已经记入日志的工具调用和消息仍在原线程上下文中。

如果传输中断时某个外部命令仍在运行，它可能已经产生副作用，但完成事件尚未
写入日志。继续后的智能体应先检查工作树和进程状态，再决定是否重复不可幂等
操作。

## 不会改变什么

- 不修改 Codex Desktop 或 app-server；
- 不改变模型选择，也不启用模型 fallback；
- 不移除内部重连等待或 `1/5` 限制；
- 不启动或关闭 Desktop；
- 默认不处理启动前已经存在的历史错误。

程序在一轮正式失败以后工作。此时可以在不杀死活动轮次的情况下安全地向原
线程排入继续消息。若要删除正在进行的内部重连等待，需要修改 Codex 内部的
传输重试实现。

## 并发注意事项

监视器处理失败时不要同时手动点击“继续”，否则两边都可能排入一条继续消息。
进程锁可以防止同一个用户同时启动两个监视器，但无法阻止手动 UI 操作。
